# Customer Data Quality & Validation System

## Project Overview

The Customer Data Quality & Validation System is a mini data quality project designed to identify, validate, clean, and analyze common issues found in customer master data.

The project uses Microsoft Excel and SQL to demonstrate practical data validation, data cleaning, duplicate identification, data verification, and data quality measurement.

The dataset contains customer information such as Customer ID, Customer Name, Email, Phone, City, State, Date of Birth, Registration Date, and Customer Type.

---

## Objectives

The main objectives of this project are:

- Identify duplicate customer records
- Detect duplicate Customer IDs
- Identify missing or blank fields
- Validate email formats
- Validate phone numbers
- Identify incomplete customer records
- Detect potential duplicate customers caused by spelling variations
- Clean and standardize customer data
- Verify records against defined data quality rules
- Measure overall data quality
- Use SQL queries to identify problematic records

## Dataset

The customer master dataset contains the following fields:

| Column | Description |
|---|---|
| Customer ID | Unique identifier assigned to each customer |
| Customer Name | Full name of the customer |
| Email | Customer email address |
| Phone | Customer phone number |
| City | Customer city |
| State | Customer state |
| Date of Birth | Customer date of birth |
| Registration Date | Date when the customer registered |
| Customer Type | Customer classification such as Regular or Premium |

The raw dataset contains intentionally introduced data-quality issues to simulate real-world customer master data.

---

## Data Quality Issues Introduced

The dataset contains realistic data problems such as:

- Duplicate Customer IDs
- Duplicate customer records
- Missing email addresses
- Invalid email formats
- Invalid phone numbers
- Missing city or state
- Missing date of birth
- Blank fields
- Spelling variations in customer names
- Potential duplicate customers

These issues are intentionally included so that validation and cleaning processes can be demonstrated.
